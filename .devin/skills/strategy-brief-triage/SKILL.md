# Strategy brief triage

Generated by `app/services/strategy_report.py` from `insights_engine.py`
metrics + an LLM action list (`_llm_actions`, DMR provider). Emits an email +
Slack post + "Agent deployment block" JSON (`_parse_playbook_item`).

## Playbook → queue loop (since PR #951)

The playbook is no longer advisory-only: `execute_report_actions()`
(`strategy_report.py`) parses each action into a `PlaybookItem`, converts
to `MonetizationAction`, and runs the shared
`monetization_executor.schedule_report_actions` chain (copy → quality ≥90
→ media → brand compliance ≥3 → SCHEDULED post). Details:

- **Dedup:** `posts.meta_data['strategy_action']` hash per (brief date,
  platform, instruction) — reruns skip with "already scheduled". Tag is
  `meta_data.source = 'strategy-brief'` (monetization uses its own keys).
- **Slots:** target = *tomorrow* Athens (`target_date`); dead-night times
  remap to `_PLATFORM_BASELINE`; DB slot conflicts shift +30 min ×3.
- **Video-only platforms** (tiktok/youtube/snapchat) land as DRAFT, never
  schedule an image post that would fail publish validation.
- **Triggers:** `daily_strategy_brief` notebook param `execute=True`
  (default) with a connected-accounts gate; code-path runner
  `run_strategy_report_for_all_teams(execute=True)` covers the
  `fallback_to_code` path too.
- **Verify in Postgres:** `SELECT meta_data->>'source', status, count(*)
  FROM posts WHERE created_at::date = today GROUP BY 1,2` — expect
  `strategy-brief` rows. The brief email renders them under
  "Queued by the platform".

## Failure signatures (verified from notebook outputs 2026-10)

| Signature | Root cause | Status |
|---|---|---|
| `Strategy report inference failed: 502: DMR failed after retry: ReadTimeout` | DMR call exceeds timeout under GPU contention (gpu-arbiter waits 480s then proceeds unserialized; ComfyUI crowds the 8GB card at the 09:00 EET run) | OPEN — reserve a GPU slot for the brief or let CF Workers AI fallback trigger on ReadTimeout |
| `Strategy LLM reply produced no actions (provider=None): [{'platform': …}]` | Model answered a Python-repr dict list (single quotes); `json.loads` rejected it → `_parse_actions` returned nothing | FIXED — `ast.literal_eval` fallback + `{platform,time,format,reason}` recomposition (`_action_entry`) |
| Model wraps actions in prose / truncated JSON | `literal_eval` can't recover those | if seen again: `pip install json-repair` (MIT, FOSS — benchmarked best stdlib-adjacent repair lib) as a third parse stage before line-matching |
| `Rule-based recommendations (AI writer unavailable)` in email | Either of the above → `llm_used=False`; playbook degenerates to LinkedIn outlier notes with no times/formats | symptom, not root cause |
| Playbook items missing platform | prose `_parse_playbook_item` couldn't resolve → `execute_report_actions` drops them silently | by design; check brief actions text |

## History cross-check (auditing the brief over time)

The brief is **email-only** — no DB copy exists; the mailbox is the
archive. Day 1 = 2026-09-21 (feature landed `ff178b20`).

```bash
# pull every brief into /tmp/briefs/YYYY-MM-DD.txt
python3 scripts/fetch_briefs.py            # reads SMTP_PASSWORD from repo .env

# tabulate the series: 24h metrics, followers, sync gaps, AI-vs-rule days,
# dead-night playbook recommendations
python3 scripts/brief_metrics.py /tmp/briefs
```

Cross-check the series against live truth before concluding:
`follower_snapshots` (per-account first/latest), `post_targets` status
counts, `posts.meta_data->>'source'` for executor output, and
`scripts/monetization_tool.py report` for gate ETAs. Known series traps:
pre-2026-09-25 briefs have no `has N followers` pulse cells (don't read
the Posts column as followers); monetization table appears from 10-03;
the 24h impressions jump mid-October is partly a metric-method change.

## What the numbers actually measure

- **Best window** — learned from the timestamps of *our own published posts*
  (`p["hours"]`/`p["weekdays"]` buckets by `published_at` Athens hour, avg
  engagement-rate per bucket, `min_n=3`). It is **not** audience-online data.
  Any recurring automation slot can win the bucket and masquerade as a best
  time. Dead-night hours (00:00–05:59 Athens) are suppressed as scheduler
  artifacts since PR #143 — both in the pulse table (renders "baseline") and
  in the LLM input (`_compact_insights` withholds `best_hour_athens`).
- **Momentum (`+N%`)** — week-over-week engagement delta on *whatever tiny
  base exists*. `+830%` on a 20-follower account is real math, meaningless
  signal. Always read absolute counts next to it.
- **Avg ER** — engagement/impressions across synced posts; LinkedIn member
  posts report impressions≈0 (no API path), so member ER is inflated/missing.
- **vs benchmark** — gated at `_BENCHMARK_MIN_FOLLOWERS = 50`; every account
  currently shows "needs 50+ followers". `benchmark_verdict` / sentinels are
  intentional, not missing data.

## Honest external limitations (do NOT "fix" by paying)

- `twitter stats HTTP 401/402` — X free API tier has no timeline/stats read.
  `quota_exhausted` is expected; the sync reports it and continues.
- `member_postAnalytics_scope_missing` — personal LinkedIn post analytics
  need restricted scopes; sidecar scrape is the only path (may be dead —
  see session-health-ops).
- `imp 0` top posts — member-post impressions aren't retrievable.

## Before executing a playbook action

The JSON block is advisory — parsed from LLM text (`_parse_playbook_item`),
not a scheduler. Check per action:

1. Platform row has non-trivial posts/impressions AND confidence isn't "low".
2. Time is inside sane local hours — a 00:00–06:00 recommendation means the
   dead-night guard missed it; remap to the platform baseline window instead
   (LinkedIn B2B ≈ 08:00–10:00 Athens weekdays).
3. `media_required: true` — confirm a real asset exists / can be generated
   (IG needs image or carousel, TikTok needs video).
4. Do not weight effort by momentum % on sub-50-follower accounts.

## Related knobs (strategy_report.py)

- `_MAX_ACTIONS` = 6 — one per platform, chronological.
- `_best()` `min_n=3` — raise this if thin buckets keep winning.
- The LLM prompt hard-bans 00:00–06:00 Athens; dead-night best-hour data is
  withheld entirely in `_compact_insights` (keeps `best_hour_sample` for
  transparency on daytime hours).
