# Monitoring Ops

Prometheus + Grafana live in k3s namespace `monitoring` on the omv host.
Reach them over **Tailscale SSH to omv** (primary path — no local kubeconfig):

```bash
ssh omv  # tailscale host 100.74.191.58
sudo kubectl --kubeconfig /etc/rancher/k3s/k3s.yaml -n monitoring get pods
```

- Grafana: NodePort `30850` (`kube-prom-grafana`), auto-loads ConfigMaps
  labelled `grafana_dashboard=1` (or the folder convention used by
  `deploy/monitoring/*/dashboard-*.json` → apply.sh creates them).
- Prometheus: `kube-prom-kube-prometheus-prometheus`. Targets at
  `/api/v1/targets`; key jobs: `socialauto`, `espocrm`, `selfhosted-*`,
  `tunnel-*`.

## SocialAuto metrics (`social-metrics` container → `192.168.1.23:9390/metrics`)

Generated by `app/services/metrics.py` (refresh loop, real Postgres queries —
never mocks). Base series: `socialauto_social_accounts`, `socialauto_posts`,
`socialauto_publish_queue`, `socialauto_media_assets`, AI usage/cost,
HTTP counters+latency.

**Per-platform series added 2026-10-19 (PR #736)** — all joined through
`social_accounts.platform`:

| Metric | Source | Panel use |
|---|---|---|
| `socialauto_publish_queue_platform{platform,status}` | publish_queue→social_accounts | queue depth/status per platform |
| `socialauto_posts_published_7d{platform}` | posts.published_at | 7d throughput |
| `socialauto_publish_failures_7d{platform}` | targets failed recently | failure bars |
| `socialauto_followers_latest{account,platform}` | follower_snapshots latest | follower table/trend |
| `socialauto_token_expires_in_seconds{account,platform}` | social_accounts.token_expires_at | expiry countdown — alert <72h |

Gotchas: `post_targets` has NO `platform`/`error` columns — join
`social_accounts` for platform, use `error_message`. Tests fake 11+ queries
in `tests/unit/test_metrics_service.py` — update the fake DB when adding a
series.

## EspoCRM exporter (k3s `espocrm` namespace)

EspoCRM (PHP) has no `/metrics` — `deploy/monitoring/espocrm/exporter.py` is a
small Python http server that queries **espocrm-mariadb directly**
(`espocrm-mariadb:3306`, db/user `espocrm`, password from secret
`espocrm-secrets` key `mariadb-password` — referenced, never committed).
Deployment `espocrm-exporter` + Service `:8080` + ServiceMonitor (60s scrape).

Real series: `espocrm_up`, `espocrm_leads_total{status}`,
`espocrm_leads_created_24h`, `espocrm_leads_by_source{source}`,
`espocrm_target_list_members{list}`, `espocrm_campaigns_total{status}`,
`espocrm_notes_24h{type}`, `espocrm_jobs{status}`, `espocrm_job_failures_24h`,
DB size. Lead↔TargetList join table is `lead_target_list`; job queue table
is `job{status,execute_time}`.

## Manifests + dashboards (repo)

`deploy/monitoring/<area>/` convention — manifest(s) + `dashboard-*.json` +
`apply.sh` + `README.md`:

- `deploy/monitoring/socialauto/` — Service/Endpoints→192.168.1.23:9390,
  ServiceMonitor (30s), `dashboard-social-platforms.json`
- `deploy/monitoring/espocrm/` — exporter Deployment/Service/ServiceMonitor,
  `dashboard-espocrm-vitals.json`
- Dashboard ConfigMaps live: `grafana-dashboard-social-platforms`,
  `grafana-dashboard-espocrm-vitals`, `grafana-dashboard-socialauto-vitals`,
  `grafana-dashboard-cloudflare-tunnel`, `-nextcloud`, `-selfhosted-health`,
  `-selfhosted-slo`, `-tailscale-status`, `-tunnel-sites-health`

Apply: `deploy/monitoring/<area>/apply.sh` (run from omv or with remote
kubeconfig). Validate dashboard JSON before apply (`python3 -m json.tool`).

## Verify a target

```bash
# from omv
curl -m 10 http://192.168.1.23:9390/metrics | head
kubectl --kubeconfig /etc/rancher/k3s/k3s.yaml -n espocrm \
  port-forward svc/espocrm-exporter 8080:8080 &
curl localhost:8080/metrics
# Prometheus target status
curl -s 'http://<prometheus>:9090/api/v1/targets' | python3 -c \
  "import json,sys; [print(t['labels']['job'],t['health']) for t in json.load(sys.stdin)['data']['activeTargets']]"
```

If `up{job="socialauto"}=0` but the container is healthy: Docker Desktop
restart broke the Windows port-proxy for 192.168.1.23:9390 →
`docker restart social-metrics` (see social-stack-ops).
